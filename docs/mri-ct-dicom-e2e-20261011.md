Подготовлен синтетический DICOM-фантом из 54 кадров 224×224. Реального КТ-образца среди доступных файлов не найдено: файлы каталога CT-просмотрщика также имеют модальность MR.

В работающем `ml_exam_service` воспроизведена ошибка `ValueError: too many values to unpack (expected 5)`. Grayscale-маска `(54,224,224,1)` превращалась в шестимерный тензор.

Исправлено удаление последней единичной размерности. Изолированный запуск с реальными весами вернул три вероятности с суммой 1; два unittest проверили совместимость входов `(N,H,W)` и `(N,H,W,1)` и отклонение RGB. ML-сервис обновлён по разрешению пользователя.

Свежая сквозная загрузка прошла через `ktupload → ktprepared → ktprocessed`. Оригинал совпадает по SHA-256, производный MP4 имеет MIME `video/mp4` и декодируется в 54 кадра. В bucket `kt-b` сохранены `mask.mp4`, `detected_video.mp4`, `video_mask_multiplied.mp4`. GET `/kt/1c543089-0d40-4868-89d8-5eab078a7dbf` вернул `completed` и вероятности: доброкачественный фенотип 0,6268467307; злокачественный 0,3270406127; неопределённый 0,0461126231. Сумма равна 1 с погрешностью менее 1e-4. Это техническая проверка на фантоме, а не клиническая оценка.

Первая попытка КТ `ea9c7a7d-ed21-48b7-a8ab-7ff61ec2afe2` выявила несовпадение номеров полей `KtProcessed` (ML: 1/2, backend: 100/200) и заглушку GET в composition-api. Исправления проверены новой загрузкой; первоначальная попытка не считается успешной.

## Исправления по результатам проверки

- МРТ-TIFF теперь одноканальный 16-битный: RGB-вход останавливал модель, ожидающую один канал; нормализация модели рассчитана на диапазон 255×255.
- Пустой результат МРТ больше не вызывает пустой SQL INSERT и переводит исследование в `completed`. Для существующего исследования без находок список узлов возвращается пустым.
- КТ загружается и конвертируется в bucket `kt-b`, из которого читает МЛ, вместо ошибочного bucket `mri`.
- КТ-предсказания корректно читаются из JSONB; статус проходит `pending → completed`; HTTP-ответ содержит вероятности классов.
- GET КТ теперь вызывает существующий exam-адаптер вместо возврата пустого объекта; ML protobuf приведён к существующим номерам полей backend 100/200.
- DICOM КТ короче 54 кадров отклоняется до события МЛ, поскольку модель требует не менее 54 кадров.

Первоначальные технические попытки `ab677b87-06fb-4e65-a9b5-1e841b716dab` и `b425fcc4-58e9-4b99-8f1b-238c825d1246` обнаружили ошибки RGB-входа и пустого SQL INSERT. Их нельзя считать успешными проверками. У первой попытки производный TIFF был исправлен отдельно, чтобы прекратить повторные падения consumer; успешные проверки выше выполнены новыми загрузками через исправленный backend.
